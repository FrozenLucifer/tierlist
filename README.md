# Локальный тир-лист объектов

Универсальное офлайн-веб-приложение для парных сравнений любых объектов (книг, фильмов, игр и т.д.). Сравнивает два объекта за раз, сохраняет результаты в SQLite и показывает итоговый рейтинг. Сервер слушает только `127.0.0.1`, так что извне сети он недоступен.

## Что нового в universelle версии

- **Любые объекты, не только картинки.** У каждого объекта есть название, описание и опциональная картинка. Картинка больше не обязательна — объект может быть чисто текстовым.
- **Описание с гипертекстом.** В описание можно вставлять HTML-ссылки (`<a href="...">`), жирный (`<b>`), курсив (`<i>`) и другое. Гиперссылки открываются в новой вкладке.
- **Без картинки — просто текст.** Если картинки нет, объект отображается как текстовая карточка с названием и описанием. Если картинка есть — название отображается под ней.
- **Добавление объектов вручную.** Можно создавать объекты через интерфейс, загружать к ним картинку (опционально) и редактировать название/описание позже.
- **Все старые сравнения сохраняются.** См. скрипт миграции ниже.

## Быстрый старт в Windows

Откройте PowerShell в папке проекта и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m tierlist_app --folder "C:\Путь\к\папке"
```

Затем откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). В дальнейшем достаточно активировать окружение и выполнить последнюю команду. Параметр `--folder` необязателен: путь к папке с изображениями можно ввести на странице, а объекты можно добавлять и вручную. Для остановки нажмите `Ctrl+C` в PowerShell.

Если PowerShell запрещает запуск активационного скрипта, вместо него используйте:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m tierlist_app --folder "C:\Путь\к\папке"
```

## Миграция со старой версии (только изображения)

Если у вас уже есть база сравнений из старой версии, скрипт `migrate_to_universal.py` перенесёт все объекты, медиа-пути и историю сравнений в новую универсальную схему. Названия объектов берутся из `C:\goods\author_today_export\author_today_biblioteka.xlsx` (столбец «Название цикла / книги»), если имя файла совпадает с названием из этого файла — иначе остаётся исходное имя файла (потом можноrename в интерфейсе).

Перед запуском делается бэкап старой базы в `data\migration_backups\`.

```powershell
python migrate_to_universal.py
```

После миграции запускайте приложение как обычно: `python -m tierlist_app`.

## Данные и устойчивость

База находится в `data\tierlist.sqlite3`; это единственный файл с прогрессом. SQLite использует журнал WAL, поэтому изменения фиксируются после каждого решения. Загруженные картинки хранятся в `data\uploads\`.

При синхронизации исчезнувшие файлы лишь становятся недоступными: история, рейтинг и записи о них не удаляются. Когда такой же файл снова появится, он вернётся с прежней историей. Повреждённые, нечитаемые и неподдерживаемые файлы пропускаются. Поддерживаются JPG, PNG, GIF, WebP и BMP; SVG намеренно исключён.

В таблице рейтинга есть удаление с обязательным подтверждением. Для существующего объекта кнопка удаления убирает все прикреплённые медиа и все связанные с ним сравнения. Для недоступного объекта доступно удаление только истории. После такой операции рейтинги остальных объектов пересчитываются. Операция необратима.

## Как выбираются пары

Используется онлайн-вариант модели Bradley–Terry: вероятность предпочесть A вместо B равна `sigmoid(rating_A - rating_B)`. После выбора рейтинги обновляются градиентным шагом, а полный журнал решений позволяет точно пересчитать их при отмене последнего действия.

Для каждой возможной пары вычисляется приоритет:

`(0.12 + 0.88 × 4p(1-p)) × (1/√(games_A+1) + 1/√(games_B+1))`.

Первый множитель максимален при близких рейтингах (`p≈0.5`), поэтому уже очевидные верх и низ сравниваются редко. Второй чаще выводит новые и мало изученные объекты. Небольшой случайный множитель и штраф недавно показанных пар не дают интерфейсу повторять один и тот же матч.
